Refine the L2 container view.

The seed creates one container per detected unit (go.mod / package.json /
pyproject.toml). In a monorepo that's usually too many — most units are
libraries, not deployables.

1. Read `build/raw/manifest.json` and inventory the detected units.
2. In `build/raw/source/`, find deploy signals:
   - `Dockerfile`, `docker-compose.yml`, `k8s/**/*.yaml`, `Procfile`
   - `.github/workflows/` (look for `docker build`, `deploy`, `helm`)
   - `Makefile`, `Taskfile.yml`, `justfile`, npm `"scripts"` in
     top-level `package.json`
   - Entrypoints: `main.go`, `__main__.py`, `bin/`, `cmd/<svc>/main.go`,
     `ENTRYPOINT`/`CMD` lines
3. Classify each unit as one of:
   - **Deployable process** — runs as its own container/service (web
     server, worker, CLI, scheduled job)
   - **Shared library** — consumed by deployables, not run standalone
   - **Datastore** — PostgreSQL, Redis, Kafka, S3 (should become a
     container with `tag "Database"` or `tag "Queue"`)
4. Edit `out/workspace.dsl`:
   - Merge shared-library containers into their consumer container (delete
     the library container; its contents become extra components inside
     the consumer).
   - Add datastore containers with appropriate tags.
   - Ensure inter-container relationships have verb-phrase labels tied to
     real call/import edges.
5. Re-render Mermaid previews. Ask the user to confirm before `/l1`.
