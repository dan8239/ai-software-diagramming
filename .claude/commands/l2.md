Refine the L2 container view.

The seed treats every package as its own container. That's almost always
wrong. Inspect the repo to determine real deployable units:

1. Read `build/raw/source/pyproject.toml` (or `setup.py`/`setup.cfg`) for
   declared entrypoints, scripts, optional dependencies.
2. Look for `Dockerfile`, `docker-compose.yml`, `k8s/`, `.github/workflows/`,
   `Procfile`, `bin/`, top-level `__main__.py`, `cli.py`.
3. Decide which packages are:
   - a deployable process (CLI tool, web server, worker, scheduled job)
   - a library (consumed by the deployables)
   - a datastore reference (DB, cache, queue) — model as container with
     `tag "Database"` or similar
4. Edit `out/workspace.dsl`: merge package-containers into deployable-
   containers, demote pure libraries to components within them.
5. Add inter-container relationships with verb-phrases derived from real
   call/import edges.
6. Re-render Mermaid. Ask the user to confirm before `/l1`.
