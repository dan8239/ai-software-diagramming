Refine the L2 container view.

The seeder already did coarse cleanup:
- **Deployable detection** — units with `Dockerfile`, `main.go`, `__main__.py`,
  `cmd/*/main.go`, `[project.scripts]`, or npm `"bin"` / `"start"` / `"dev"`
  scripts are tagged `Service`.
- **Library collapse** — non-deployable units with exactly one cross-unit
  consumer were merged into that consumer; their components became
  components of the consumer container (look for `Merged from … library`
  descriptions in `out/workspace.dsl`).
- **Shared libraries** — non-deployable units imported by >1 consumer
  were kept as their own containers with a `Shared Library` tag.
- **L2 partitioning** — when there are many containers across multiple
  top-level dirs, per-dir views (`L2_<dir>`) were emitted alongside
  `L2_all`.

Your refinement job:

1. **Review the seeder's summary** (printed when `seed_structurizr.py`
   ran; also implied by the `tags "Service"` / `Shared Library` / `Library`
   lines in `out/workspace.dsl`). Override anything wrong.

2. **Promote datastores/queues** that show up in `imports/*.json` externals
   into their own containers, tagged `"Database"`, `"Queue"`, or
   `"Cache"`. E.g. `postgres` referenced from `database/sql` + `lib/pq`
   → add a `postgres = container "PostgreSQL" "..." "PostgreSQL"` with
   `tags "Database"`, and relationships from the services that use it.

3. **Prune orphan libraries** — units with zero consumers that are also
   not deployable are usually tooling, examples, or dead code. Ask the
   user whether to keep them in the model.

4. **Label every inter-container relationship** with a verb-phrase tied
   to a real call or import edge ("publishes orders to", "reads catalog
   from", "authenticates via"). Blank or "uses" labels are not
   acceptable.

5. Re-render:
   ```bash
   structurizr-cli export -workspace out/workspace.dsl -format mermaid -output out/views
   python scripts/render_drawio.py --yes
   ```
   Ask the user to confirm before `/l1`.
